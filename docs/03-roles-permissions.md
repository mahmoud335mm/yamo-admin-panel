# أدوار وصلاحيات لوحة Yamo

## الأدوار الجاهزة

| الدور | استخدامه الصحيح |
|---|---|
| `super_admin` | المالك؛ كل الصلاحيات وإدارة المسؤولين والتخصيصات. |
| `admin` | مدير تشغيل عام، دون أسرار الخادم أو تجاوزات المالك. |
| `finance` | الشحن والسحب والمحافظ والتسويات فقط. |
| `moderator` | البلاغات والعقوبات والمحتوى والغرف. |
| `agency_manager` | الوكالات والمضيفون والتسويات الخاصة بهم. |
| `support` | قراءة بيانات المستخدم والرد على تذاكر الدعم. |
| `auditor` | قراءة المؤشرات والمالية وسجل العمليات دون تعديل. |
| `viewer` | مشاهدة أساسية فقط. |

## التخصيص لكل مسؤول

كل مسؤول يبدأ بصلاحيات دوره، ثم يمكن للـSuper Admin ضبط أي صلاحية بثلاث حالات:

- `grant`: سماح مباشر حتى لو الدور لا يملكها.
- `deny`: منع مباشر ويتغلب على سماح الدور.
- `inherit`: إلغاء التخصيص والرجوع إلى صلاحيات الدور.

أمثلة متاحة بصورة مستقلة:

- `users.suspend`: إيقاف مؤقت فقط.
- `users.ban`: حظر نهائي.
- `users.warn`: تحذير فقط.
- `users.room_ban`, `users.message_ban`, `users.post_ban`, `users.call_ban`: كل عقوبة منفصلة.
- `notifications.events_send`: رسائل الحفلات والفعاليات فقط.
- `notifications.marketing_send`: الإعلانات الجماعية.
- `notifications.system_send`: رسائل النظام.
- `banners.manage`: بنرات الرئيسية فقط.
- `recharge.review`, `withdraw.review`, `economy.adjust`: مراجعة الشحن، السحب، وتعديل الرصيد كل واحدة منفصلة.

كل تغيير في الدور أو الصلاحية يسجل في `yamo_admin_audit_logs`. لا يستطيع المسؤول منع صلاحية إدارة المسؤولين عن نفسه، ولا يمكن وضع منع مباشر على حساب Super Admin.
